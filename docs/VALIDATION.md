# 패턴 전환 검증 기록

검증일: 2026-10-13. 브랜치: `feat/orchestrator-workers`. 이 기록은 모의 결과와 실제 서비스 실행을 구분한다.

## 자동 검증

- 기존 185개 테스트를 보존했다.
- 동적 7/3/4 작업 계획, 원문 없는 캐시 거부, 0개 작업 직접 집계, 최소 Send 입력, 실제 Send fan-in 한 번 집계.
- 결과 병합의 순서 독립성·멱등성·충돌 거부, Overwrite 초기화, worker 1회 재시도·인증 오류 전파·부분 실패와 캐시 보존.
- 피드백 재생성 후 통과, 최초 포함 3개 버전 미달 종료, Judge 실패 시 통과 거부, 투자·전체 보류·후보 없음, 최신 버전·PDF hash 검사.
- 원문 없는 수치·인용 원문과 모순·기술 홍보·출처 편중은 코드 검사에서 거부하며, 유효 ID지만 지지되지 않는 주장은 Judge에 발췌를 전달해 검사한다.
- 병렬 근거 캡처 격리, 미사용 출처 제외, 원본 페이지·발췌문 보존, 수치와 출처의 연결·천 단위 쉼표 처리.
- 리뷰의 3결함 회귀를 먼저 추가해 수정 전 **18 failed / 18 passed**를 확인했다. 수정 후 관련 검사 **143 passed**, 전체 `.venv/bin/python -m pytest -q -p no:cacheprovider` **277 passed**(기존 219 + 회귀 58)를 확인했다.
- TRL 평가의 State 값·판단근거·기술 출처 연결을 생성/품질 양쪽에서 검사했다. 원문에 TRL 숫자가 없는 정상 평가를 허용하며, State 불일치·동일 값의 시장 용량·무인용·다른 관점 출처를 거부한다. 원문 금액·단위 보존 규칙에 따라 `$20 million`→`2000만`은 계속 거부한다. 의미·범위·단위 판단은 독립 Judge가 유지한다.
- failed/insufficient 성장 작업 + success 규제 작업을 캐시 유무·target_fields 제한별로 재현했다. 유효 기존 필드 보존, 성공한 부족 필드 갱신, 캐시 없는 실패 관점의 fallback, 성공한 전체 시장 작업 합류·캐시 재발행을 확인했다.
- 실제 HfHubHTTPError 클래스로 인메모리 401/403을 만들고 worker가 1회 호출 후 ConfigurationError를 전파하는지 검사했다. requests/httpx/HF의 400/401/403, 공급자 fatal 오류와 missing HF_TOKEN, 408/429/5xx·연결·timeout 분류 및 HF transient 2회 상한을 검사했다. 실제 외부 호출·유료 실험·최종 보고서 품질 통과 실험은 이번 수정 검증에 포함하지 않았다.
- 문서 검사: **195/200쪽**, 기술 231개·시장 90개 청크. 모델 호출·벡터스토어 변경 없이 검사했다.
- 평가셋 검사: 기술 **20/20**, 시장 **30/30** 질문. 기존 PDF 일부의 객체 offset 경고와 DOE 59쪽 텍스트 없음 경고가 있으며 청크·정답 페이지 검사는 통과했다.

## 실제 LangSmith 실행

LLM_MODEL과 JUDGE_MODEL은 기존 환경의 `gpt-4o-mini`를 사용했다. 시드 후보를 선택하고 실제 LLM·웹 검색·RAG를 실행했다.

1. [전체 그래프 trace](https://smith.langchain.com/o/9f11065d-205c-42b4-a4fd-a6b3e8cf79de/projects/p/0517a558-40a2-4809-9495-a00c50123fde/r/631dea9d-663a-4862-b384-e83f43209a55?poll=true): 해줌 7개 → 식스티헤르츠 3개 → Amperon 7개. 식스티헤르츠는 유효 시장 캐시를 재사용했다. 서버 API에서 trace 존재와 URL을 확인했다.
2. [품질 개선·미달 종료 trace](https://smith.langchain.com/o/9f11065d-205c-42b4-a4fd-a6b3e8cf79de/projects/p/0517a558-40a2-4809-9495-a00c50123fde/r/f0f1876a-f9aa-4b14-95f0-2ffe8bd25aae?poll=true): 위 실제 실행에서 저장한 분석·발췌를 재사용한 **보고서 구간 검증**이다. v1 미달 → 피드백 반영 v2 → v3 상한 종료를 실제 LLM으로 확인했다. 전체 그래프 재실행으로 표시하지 않는다.

실제 응답에서는 인용 원문에 없는 숫자, 시장 범위 혼동, SUMMARY 분량 초과, SUIT 미지원 문자 등이 발생했다. 이 결과를 자동 통과시키지 않았다. 생성 단계 수치 검사와 구조화 인용·분량 목표·조판 오류 피드백 처리를 보완했다. 최신 코드에서도 원문에 없는 수치가 남으면 정상적으로 `quality_failed`가 된다.

실제 품질을 모두 통과한 최종 보고서는 아직 확보하지 못했다. 검토용 PDF·Markdown·JSON·품질 이유는 각 `outputs/runs/{run_id}/`에 보존된다. 실제 검토용 4쪽 PDF의 전체 페이지를 PNG로 렌더해 한글·표·SUMMARY·REFERENCE·페이지 배치를 확인했다. 이 시각 검사는 근거성 통과를 의미하지 않는다.
